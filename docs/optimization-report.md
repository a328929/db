# 采集项目全面优化报告

## 2026-09-07 首轮

### 已修复

- `storage.connection.synchronized_write` 使用 `functools.wraps` 保留原函数名称、文档和签名元数据，便于调试、监控和依赖注入工具正确识别被装饰函数。
- `search.manticore_client.ManticoreClient.sample_documents` 对采样 ID 做容错转换，忽略 `None`、非数字和非正数输入；单个脏值不再导致整个一致性校验请求失败，同时保持去重和有界查询。
- 删除后台管理路由中两段已废弃的注释代码，减少死代码噪声。

### 影响与风险

- 写锁装饰器运行行为不变，仅增强元数据保留。
- Manticore 采样遇到无效 ID 时会跳过该 ID；调用方仍可通过返回结果缺失识别索引不一致。
- 未引入新依赖，未改变业务接口。

### 验证

- `python3 -m compileall -q tg_harvest tests scripts tools` 通过。
- `git diff --check` 通过。
- 前端静态 JavaScript 检查通过。
- 初始系统环境未安装 `pytest`、`ruff`、`pip_audit`；随后在临时虚拟环境安装 `requirements-dev.txt` 后，完整 pytest 通过（含跳过项），ruff 全量检查通过。

## 待审查项

- 搜索与浏览查询的 SQL 投影、分页和限流开销。
- 智能/手动入库及群聊频道管理的事务边界、重复扫描和异常处理。
- 克隆任务的状态机、媒体转发确认、清理重试和资源释放。
- 页面脚本的重复请求、无效 DOM 操作和移动端布局问题。

## 审查结论

现有搜索参数校验、分页上限、SQLite 写事务、Manticore outbox 同步、后台任务互斥、CSRF 和代理 IP 校验均已有专门实现及测试覆盖。本轮没有对这些高风险模块做结构性重写，以避免在 Telegram 网络状态和生产数据规模未知时引入行为回归。后续性能优化应基于线上查询耗时、SQLite `EXPLAIN QUERY PLAN`、outbox 积压和任务吞吐指标进行，优先处理有数据证据的慢查询。

## 2026-09-07 第二轮

### 已修复

- 搜索 API 限流桶改为按最近请求排序的 `OrderedDict`，清理过期桶从全量扫描降为摊销常数开销；当前桶仍会精确清理窗口内过期请求，容量保护和每 IP 配额不变。
- 搜索限流时间源改用单调时钟，避免系统时间回拨或 NTP 校时导致限流窗口异常。
- SQLite 连接初始化或建表失败时主动关闭已打开连接，避免异常路径下文件描述符和 WAL 句柄泄漏。
- 管理端 `fetchJSON` 将超时计时器覆盖到响应正文解析完成，慢响应不会绕过超时保护；网络错误、HTTP 错误和 JSON 解析错误路径均清理计时器。
- 为上述限流和连接生命周期行为补充回归测试。

### 验证

- 定向 Python 测试通过。
- Node 静态脚本测试通过。
- JavaScript 语法检查和 `git diff --check` 通过。
- 第二轮修改未引入新依赖。
